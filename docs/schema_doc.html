JSON Schema 规范

这份文档详细定义了表单构建器前后端交互的底层数据协议。
所有组件在画布中的操作，最终都会序列化为这份 JSON，供后端入库及渲染。

1. 根数据结构 (Root)

整个表单最终会被打包成一个 JSON 对象，结构如下：



{
  "schemaVersion": "1.0.0",
  "meta": {
    "title": "用户入职登记表",
    "description": "请填写真实的个人信息"
  },
  "pages": [],
  "pageConnections": []
}

Root 字段说明

  • schemaVersionString: 协议版本号，当前固定为 "1.0.0"，方便未来做向前兼容。
  • metaObject: 表单全局的元数据，默认取自第一页画布的标题和描述。
    • titleString: 表单名称。
    • descriptionString: 表单整体说明。
  • pagesArray<Page>: 表单页面列表，支持多页表单。
  • pageConnectionsArray: 预留给页面的流向、条件跳转连线数据。

2. 页面结构 (Page)

每一个页面代表画布中的一个 Mobile Frame，结构如下：



{
  "id": "page_1717800000000",
  "title": "第 1 页",
  "description": "页面副标题或说明",
  "fields": []
}

Page 字段说明

  • idString: 页面的唯一标识符，基于时间戳生成。
  • titleString: 当前页的标题。
  • descriptionString: 当前页的副标题或提示语。
  • fieldsArray<Component>: 该页面内直接挂载的所有表单组件（按从上到下的顺序排列）。

3. 组件基础结构 (Base)

无论是输入框还是下拉菜单，所有组件都会共享以下 基础属性：



{
  "id": "cmp_1",
  "type": "input",
  "label": "姓名",
  "key": "input_1",
  "required": true,
  "showLabel": true,
  "help": "请与身份证保持一致",
  "defaultValue": "张三"
}

基础字段说明

  • idString: DOM 节点的唯一 ID，也是系统内的唯一标识。
  • typeString: 核心字段，决定了当前组件的类型。
  • labelString: 组件标题文本。即使标题被隐藏，该字段仍会保存，方便后台管理和后续恢复显示。
  • keyString: 后端入库的重要标识，建议后端基于此 Key 映射数据库字段。
  • requiredBoolean: 是否必填，控制前端校验拦截。对于 signature 组件，该字段只表示签名区域是否必填。
  • showLabelBoolean: 是否在用户端/预览端展示组件标题。默认 true；电子签名组件默认 false，通常由签名提示文案承担说明作用。
  • helpString: (可选) 组件副标题，显示在标题旁边，可在画布中直接编辑。
  • defaultValueString|Array: (可选) 组件的默认值。多选组件会导出为 JSON 数组字符串，同时兼容数组或历史逗号分隔字符串导入。

4. 各组件特有属性

根据 type 的不同，组件还会携带特定的扩展属性。

文本输入类 (input / textarea)



{
  "id": "cmp_input_1",
  "type": "input",
  "label": "姓名",
  "key": "name",
  "required": false,
  "showLabel": true,
  "placeholder": "请输入内容"
}

选择类 (select / radio / checkbox)



{
  "type": "checkbox",
  "layout": "stack",
  "maxSelections": 3,
  "options": [
    {
      "label": "选项一",
      "value": "选项一"
    },
    {
      "label": "选项二",
      "value": "选项二"
    }
  ]
}

select 会额外保存 placeholder；checkbox 支持 maxSelections 限制最多选择数量；radio 与 checkbox 通过 layout 控制横向或纵向排列。

高级业务组件 (country / nationality / date)



[
  {
    "type": "country",
    "placeholder": "请选择国家",
    "maxSelections": 3,
    "options": [
      {
        "label": "中国",
        "value": "CN"
      },
      {
        "label": "美国",
        "value": "US"
      }
    ]
  },
  {
    "type": "nationality",
    "placeholder": "请选择国籍",
    "maxSelections": 3,
    "options": [
      {
        "label": "中国籍",
        "value": "CN"
      },
      {
        "label": "美国籍",
        "value": "US"
      }
    ]
  },
  {
    "type": "date",
    "label": "证件有效期",
    "placeholder": "开始日期",
    "dateType": "date",
    "dateMode": "range",
    "defaultValue": "2026-01-01",
    "endValue": "2036-01-01",
    "enableLongTerm": true,
    "defaultLongTerm": false
  }
]

country 和 nationality 默认使用系统内置选项，保存时会将当前选项列表写入 options；maxSelections 用于限制最多可选数量。

  • placeholderString: 占位提示。日期组件中会显示为开始日期或单日期提示；国家/国籍组件中会显示为未选择时的提示。
  • dateTypeString: 原生日期输入类型，支持 date、datetime-local、month、time。
  • dateModeString: 日期选择模式，single 表示单日期，range 表示起止日期。
  • defaultValueString: 单日期值；范围模式下表示开始日期。
  • endValueString: 范围模式下的结束日期，仅 dateMode 为 range 时导出。
  • enableLongTermBoolean: 是否在日期输入右侧展示“长期”复选项。
  • defaultLongTermBoolean: “长期”是否默认勾选；勾选后用户端会禁用日期输入。

电子签名组件 (signature)

电子签名组件由“声明复选项”和“签名区域”组成。它的标题可单独隐藏，签名区域必填和声明复选必填也分别配置。



{
  "type": "signature",
  "label": "授权声明",
  "showLabel": false,
  "required": true,
  "placeholder": "请在下方指定区域签名：",
  "declarationRequired": true,
  "layout": "inline",
  "options": [
    {
      "label": "本人保证以上填写的信息真实、准确、有效。",
      "value": "dec_1"
    }
  ]
}
  • showLabelBoolean: 控制外层组件标题是否展示。签名组件默认隐藏标题，避免和签名提示重复。
  • requiredBoolean: 控制签名区域是否必填，对声明复选框无影响。
  • placeholderString: 签名区域上方的提示文案，可在画布内直接编辑，也可在右侧“签名提示”配置中修改。
  • declarationRequiredBoolean: 控制声明复选框是否必须勾选。声明文字列表本身不会展示必填红星。
  • optionsArray<Option>: 声明文本列表，label 用于展示，value 作为提交值标识。

嵌套布局容器 (grid)



{
  "id": "cmp_2",
  "type": "grid",
  "layout": "grid",
  "columns": [
    {
      "id": "col_a1",
      "elements": []
    },
    {
      "id": "col_a2",
      "elements": []
    }
  ]
}

5. 组件字典速查表

组件类型 (type) UI 表现 数据结构特有字段 / 说明
input 单行文本 placeholder
textarea 多行文本 placeholder
select 下拉选择 placeholder，必须包含 options 数组
radio 单选框组 options 数组，及 layout ("inline"/"stack")
checkbox 多选框组 options, layout, 可选 maxSelections
date 日期选择 placeholder, dateType, dateMode, enableLongTerm, defaultLongTerm，范围模式包含 endValue
country 国家选择 placeholder，内置 options，支持 maxSelections
nationality 国籍选择 placeholder，内置 options，支持 maxSelections
signature 电子签名 placeholder 为签名提示，required 控制签名区域，declarationRequired 控制声明复选必填，options 数组用作声明文本
alert 提示区块 纯展示，不作为业务数据提交给后端
grid 双列栅格 包含 columns 数组嵌套子节点

7. 后端接口对接指南

GET 获取表单模板

用于在前端拉取并渲染整个表单结构。

/api/forms/template/{form_id}

请求参数： 路径参数 form_id，代表要查询的表单ID。

响应格式： 必须返回上述定义的 完整 JSON Schema，或者将其包裹在统一的响应结构中。

POST 保存/发布表单模板

当管理员在表单构建器画布中点击“保存”时触发。

/api/forms/template

请求 Body： 前端发送的 完整 JSON Schema 数据树。

处理逻辑： 后端收到后，直接将其序列化为 JSON 字符串，存入数据库即可。无需去解析内部结构。

POST 提交最终业务数据

C端最终用户填写完表单后，提交真实“答案”数据的接口。

/api/forms/submit

请求 Body： 扁平化的键值对结构（Key-Value Map）。

其中 Key 就是组件上的 key 字段；Value 则是用户输入的实际值。



{
  "form_id": "123",
  "data": {
    "real_name": "张三",
    "education": "bachelor"
  }
}

处理逻辑： 将这些字段映射到业务表的单独列中，或整存为一个 JSON。
